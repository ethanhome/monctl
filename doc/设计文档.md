# monctl 改造设计文档

## 1. 目标

1. 去掉热键(`watch`)和开机启动(`autostart`)相关功能,保留最原始的命令行功能:`scan`、`get`、`set`、`vcp`。
2. 新增 GUI,使用 **Wails**,前端用**原生 JS**,放在仓库的 `gui/` 子目录。第一版只做普通窗口应用,不做托盘常驻。
3. 核心使用场景:一台显示器接多台电脑,通过工具切换输入源,让显示器显示不同电脑的画面。
4. **保留 GitHub 上的 CI 与 Release 打包**。用户只需要在 Release 页面下载对应平台的二进制安装即可,不需要自己编译。

## 1.1 支持平台

只支持以下两个平台,其他平台不构建、不发布:

| 平台 | 架构 | 说明 |
|---|---|---|
| Windows 10 / 11 | amd64 | 纯 Go 的 CLI;GUI 依赖 WebView2 运行时 |
| macOS | arm64(Apple Silicon) | 使用私有 IOAVService API;不支持 Intel Mac |

不再支持:Linux、macOS Intel、Windows arm64。Linux 仅保留在 CI 里跑不依赖硬件的单元测试(`monitor` 包有 `unsupported.go` 兜底),不作为发布目标。

## 2. 核心约束

显示器切走输入源后,本机就无法再通过 DDC 控制它(macOS 上会被识别为虚拟显示器,Windows 上同理)。由此得出:

- **当前输入源(`get input`)就是本机所在的口**,不需要用户再标注“本机”。
- **界面只能切到其他输入源**,没有“切到本机”按钮。
- **不做自动切回、“上一个输入源”**,由用户自己决定切到哪里。
- 切回本机需要在目标电脑或显示器上操作,所以每台电脑都装这个工具。

## 3. 界面设计

### 3.1 布局

单栏布局,不做左右分栏。亮度、对比度放在输入源下方。

```
┌─ monctl ────────────────────────────────────────┐
│  Odyssey G95NC  (1)                    [↻ 刷新] │
│                                                 │
│  输入源                                         │
│   ● DP1     Mac mini                    当前    │
│   ○ HDMI2   工作PC                     [切换]   │
│   ▸ 更多 (DP2、HDMI1、USB-C、VGA、DVI)          │
│   列表为通用输入源,不代表显示器实际拥有这些接口 │
│                                                 │
│  ─────────────────────────────────────────────  │
│  亮度   ──────●──────────  60%                  │
│  对比度 ───●─────────────  30%                  │
└─────────────────────────────────────────────────┘
```

### 3.2 输入源列表

采用**垂直列表**(每个输入源一行),而不是横向平铺的卡片。

选择理由:
1. 输入源是“选一项”的单选语义,列表加实心圆点是标准表达。
2. 自定义标签(如“工作PC”)是用户决策的关键信息,一行里“接口名 + 标签 + 操作”左右对齐,标签自然成为视觉主线。
3. 每行自带“切换”按钮,一键直达,比下拉框少一步。
4. 固定列表最多 7 项加一个未知值,垂直排列长度可控,不需要横向滚动。

规则:
- 列表来源是**固定列表**:vga、dvi、dp1、dp2、hdmi1、hdmi2、usb-c(即 `monitor/vcp.go` 里已有的名称表)。第一版不读 capabilities。
- 当前输入源(`get input` 的结果)标为“● 当前”,排第一,不可点击。
- 当前输入源如果不在固定列表里,显示为原始值(如 `0x1B`),同样标为当前并排第一。
- **排序与折叠**:当前口和已设置标签的口始终展示;其余口折叠进“更多”。折叠状态不持久化,每次打开默认折叠。
- 其他口每行带“切换”按钮,标签可点击编辑,标签只用于显示。
- 列表下方常驻小字:“列表为通用输入源,不代表显示器实际拥有这些接口”。

### 3.3 亮度、对比度

- 仅当能扫描到显示器、并且读出了当前输入源时才显示并允许修改。其他情况下整块不显示,不显示灰掉的控件。
- 亮度和对比度中某一项读不出(例如面板不支持对比度),只隐藏那一项,其余照常显示。
- 亮度和对比度用百分比 0–100,按面板报告的 VCP 最大值换算(与 CLI 一致)。
- **不提供电源控制**。DDC 的待机/关机(`VCP 0xD6`)发出后,面板往往连 DDC 都不再响应,应用无法再把它唤醒,只能按显示器实体键或恢复输入信号。CLI 仍保留 `get/set power` 作为应急手段。

### 3.4 切换输入源的流程

1. 点“切换”,弹出确认框:“切换到 HDMI2(工作PC)后,本机将无法控制这台显示器。”框内有“不再提示”复选框(对应设置项 `skipSwitchConfirm`)。
2. 确认后发送 `set input`。
3. **界面保持不变**:当前标记仍在原来的口,亮度、对比度照常显示。这样用户从别的电脑切回来时,看到的仍是切走前的状态,而这个状态就是正确的。
4. 底部弹一条轻提示:“已发送切换到 HDMI2”,几秒后自动消失。不弹窗,不遮挡操作。

### 3.5 状态表

| 状态 | 输入源列表 | 亮度/对比度 | 提示 |
|---|---|---|---|
| 正常 | 显示 | 显示 | 无 |
| 扫描不到显示器 | 隐藏 | 隐藏 | “未检测到可控制的显示器”,说明可能原因:显示器正在显示其他输入源,或 OSD 里没开启 DDC/CI;提供“重新检测” |
| 扫描到显示器,但读不出当前输入源 | 显示,无“当前”标记 | 隐藏 | “无法读取当前输入源,暂不能调节亮度等设置” |

不存在“已切换”状态。

### 3.6 切走之后再操作

界面保持原样,用户可能在切走后继续拖滑块或点切换,此时 DDC 通信会失败:
- 弹轻提示“无法与显示器通信,可能已切换到其他输入源”。
- 滑块回到操作前的值,不留下假数据。
- 不改变界面状态,不自动重试。

### 3.7 刷新行为

- 点“刷新”:重新扫描并读取所有值。成功则更新界面;失败则进入“扫描不到显示器”状态(这是用户主动要求看最新状态)。
- 窗口获得焦点时**不**自动刷新,保证用户切回来时界面和切走前一致,不会因一次失败的静默扫描而突然变样。

## 4. 数据来源

| 界面元素 | 来源 |
|---|---|
| 显示器列表、型号、序号 | `scan` |
| 当前输入源 | `get input` |
| 亮度、对比度 | `get` |
| 切换输入源 | `set input` |
| 输入源行列表 | 固定列表 |

## 5. 本地设置文件

GUI 需要一个很小的设置文件,放在系统用户配置目录,**不复用**旧的 `config.go`(它是热键配置,会被删除)。

```json
{
  "skipSwitchConfirm": false,
  "monitors": {
    "G95NC-xxxx": { "labels": { "dp1": "Mac mini", "hdmi2": "工作PC" } }
  }
}
```

- 显示器标识:使用 `monitor.Info.Description`(型号)。`Info` 没有序列号,同型号的两台显示器会共用标签。
- 只存标签和 `skipSwitchConfirm`,不存任何“上一个输入源”之类的状态。

## 6. 架构

```
monctl/
├── monitor/              # 不变:DDC/CI、VCP、EDID、各平台实现
├── internal/service/     # 新增:List / Get / Set / Raw,含值解析(百分比、+N/-N、名称、0xNN),CLI 与 GUI 共用
├── internal/settings/    # 新增:读写设置文件
├── cmd/monctl/           # CLI:只做参数解析,调 service
└── gui/                  # Wails 应用(独立的 main 包),原生 JS 前端
    ├── main.go
    ├── app.go            # 暴露给前端的方法
    └── frontend/
```

要点:
- 目前 `main.go` 里的 `cmdGetSet` 等函数把值解析和输出混在一起。先把解析逻辑抽到 `service`,GUI 不重复实现,也不通过子进程调用 CLI。
- CLI 保持纯 Go 小二进制;GUI 单独用 `wails build` 构建;两者共用 `monitor` 和 `service`。

### Wails 暴露给前端的方法

- `ListMonitors()`:返回每台显示器的型号、序号、当前输入源、亮度和上限、对比度;读不出的项标记为未知。
- `SetInput(idx, name)`、`SetBrightness(idx, pct)`、`SetContrast(idx, pct)`
- `GetSettings()`、`SaveLabel(monitorID, input, name)`、`SetSkipSwitchConfirm(bool)`

### 并发与错误处理

- DDC 总线慢且不能并发,后端用一个**串行队列**执行所有 DDC 调用(思路可参考现有 `apply_worker.go`,但该文件随热键一起删除,不直接沿用)。
- 滑块拖动时前端防抖,后端只保留最新的一个值。
- 某项读不出就显示“未知”,不报错。

## 7. 要删除的内容

- `watch.go`、`apply_worker.go`、`apply_worker_test.go`
- `hotkey_*.go`(含 scrub、alt、media 及其测试)、`rawinput_windows.go`
- `autostart*.go`、`axprompt_*.go`、`modsrelease_*.go`
- `probe_input_*.go`(热键调试用)
- `config.go`,以及 `monitor/monitor.go` 里的 `Config`、`DefaultConfig`、`ConfigPath`、`LoadConfig`、`WriteDefaultConfig`(删除前再确认确实只被热键使用)
- `main.go` 里的 `watch`、`config`、`autostart`、`probe-input` 子命令
- `main_darwin.go`、`main_other.go` 里与 `mainthread.Init` 相关的逻辑(Wails 自己管理主线程)
- 依赖 `golang.design/x/hotkey`、`golang.design/x/mainthread`
- `tools/inject-mute.ps1`(热键相关)
- `tools/osd/`(热键调节亮度时的原生浮层)
- `tools/app/mkapp.sh`、`tools/app/Info.plist`:它们打的是运行 `watch` 守护进程的 `.app`(含重启循环 wrapper),随之作废;GUI 的 `.app` 由 Wails 构建生成
- 保留 `tools/app/mkdmg.sh`:它只是把 `.app` 打进 `.dmg`,与 `.app` 内容无关,可复用
- README 中热键、autostart、watch 相关的段落
- CI 里为热键 X11 初始化准备的 Xvfb 步骤
- release 里的 `monctl-tray-*.exe`(`-H windowsgui` 的静默后台版,只为 `watch` 服务)

## 7.1 CI 与 Release

### CI(`.github/workflows/ci.yml`,保留)

- 触发:push 到 main、pull request。
- 矩阵:ubuntu、macos、windows。`go build ./...`、`go vet ./...`、`go test ./...`。
- ubuntu 仅用于跑不依赖硬件的单元测试;去掉 X11 和 Xvfb 步骤。
- 保留“测试失败时把日志末尾输出为 annotation”的步骤。
- 加入 GUI 构建检查(Windows、macOS 上执行 `wails build`),确保 GUI 不会悄悄编译失败。

### Release(`.github/workflows/release.yml`,保留并收窄)

- 触发:推送 `v*` tag。
- 构建目标只有两个:
  - `windows/amd64`
  - `darwin/arm64`
- 删除目标:`windows/arm64`、`darwin/amd64`、`linux/amd64`。
- 每个平台各产出 CLI 和 GUI 两类产物:

| 产物 | 说明 |
|---|---|
| `monctl-windows-amd64.exe` | CLI,纯 Go,控制台程序 |
| `monctl-gui-windows-amd64.exe` | GUI(Wails),窗口程序 |
| `monctl-darwin-arm64` | CLI,裸二进制(需要 CGO,在 macOS runner 上构建) |
| `monctl-macos-arm64.dmg` | GUI,内含 Wails 生成的 `monctl.app`,带拖入 Applications 的快捷方式 |

- 以前 `.app` 取代了裸二进制;现在 `.app` 只是 GUI,所以 CLI 的裸二进制需要保留,不能再 `rm`。
- 命名里的 `-H windowsgui` 只用于 GUI,CLI 保持控制台程序。
- 最终由 `softprops/action-gh-release` 把 `dist/*` 上传到 Release,并自动生成 release notes。
- 构建参数继续注入版本号(`-X main.version=${GITHUB_REF_NAME}`)。目前代码里这个变量是否存在需要确认,没有就一并补上。

### 用户安装方式(写进 README)

- **Windows**:下载 `monctl-gui-windows-amd64.exe` 直接运行;命令行用户下载 `monctl-windows-amd64.exe`。
- **macOS**:下载 `.dmg`,把 `monctl.app` 拖进 Applications;命令行用户下载 `monctl-darwin-arm64`,放到 `~/bin` 等内置磁盘位置。
- 因为没有代码签名,macOS 首次打开会被 Gatekeeper 拦截,README 要写清楚处理方法(右键打开,或 `xattr -d com.apple.quarantine`)。

## 8. 不做的事(第一版)

- 读取显示器 capabilities(VCP 0xF3)以得知真实支持的输入源。后续可作为独立增强:首次扫描读一次并缓存。
- 隐藏不用的输入源。
- 托盘常驻、开机启动、全局热键。
- 自动切回、“上一个输入源”、“切换到本机”。

## 9. 风险与待确认

- **macOS 的 CGO**:`monitor/darwin.go` 依赖 IOAVService,Wails 在 macOS 也走 CGO,需要实际验证两者共存。
- **固定列表的误导性**:会显示显示器没有的口,点击结果取决于面板;靠界面小字提示缓解。
- **未知输入值**:厂商值与标准不一致时(如 Samsung),显示原始值,用户可自行起标签。
- **显示器标识**:已确认 `monitor.Info` 只有 `Index`、`Description`、`Primary`、`Handle`,没有序列号。设置文件里的显示器标识只能用 `Description`(型号);两台同型号显示器会共用标签,第一版接受这一点。
- **Windows 的 WebView2**:Wails 的 Windows GUI 依赖 WebView2 运行时。Windows 11 自带,部分 Windows 10 没有。需要决定是让 Wails 的安装引导自动下载,还是在 README 里提示用户安装。
- **macOS 未签名**:没有 Apple 开发者签名和公证,用户需要手动放行,体验较差。第一版接受这一点,后续可考虑签名。
- **Windows 构建方式变化**:CLI 原本在 Linux runner 上交叉编译。Wails 的 Windows GUI 需要在 Windows runner 上构建;CLI 可以继续交叉编译,也可以统一放到 Windows runner。

## 10. 实现记录(2026-11-17)

- 已发布 `v0.2.0`(fork `ethanhome/monctl`):CLI 与 GUI 各两个产物,只覆盖 Windows 10/11 amd64 与 macOS arm64。`v0.1.0` 已被上游占用,故从 `v0.2.0` 起。
- 电源按钮已从 GUI 下线:待机/关机后 DDC 常被面板切断,无法再从应用唤醒;CLI 仍保留 `get/set power`。
- Linux 不支持(CLI 与 GUI 均不发布),仅在 CI 中跑不依赖硬件的单元测试。
- macOS `.app` 的 bundle id 固定为 `com.bacnh85.monctl`。
- GUI 版本号由 Release 工作流根据 tag 写入 `gui/wails.json` 的 `info.productVersion`,仓库内保留占位值。
- CI 固定 `macos-15`(macOS runner 曾两次丢失 job,日志为空);action 升级到 checkout/setup-go/setup-node v7、upload-artifact v7、download-artifact v8。
